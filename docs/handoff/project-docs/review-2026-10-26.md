## Findings (priority order)

### 1. Admin API open + no CSRF protection (security, new)
- `ADMIN_TOKEN` empty in examples and live `config/autosourcarr.env` → every `/api/admin/*` route open (Python `admin_guard`, C# `AdminAllowed`).
- Compose publishes `8282` on all interfaces, so LAN access skips Authelia.
- No Origin/`Sec-Fetch-Site` check on admin routes (only `repair_connection.py`). Body-less POSTs `/api/admin/maintenance/reset-database`, `full-reset`, `reset-manual-groups`, `reset-manual-matches` can be fired by any web page you visit (`fetch(…,{method:'POST',mode:'no-cors'})`).
- Not recorded in the knowledge DB (no CSRF records).
- Proposal: same-origin middleware for non-GET `/api/admin/*` in Python and C#, typed confirmation on the 4 resets, auth-on-by-default first run.

### 2. Suwayomi published without auth
`AUTH_MODE: none` + `30058:30058`. Drop the host port, bind `127.0.0.1`, or enable Suwayomi auth. (Knowledge DB DEP-F04 is related and still open.)

### 3. Knowledge DB metadata stale after the folder move
`workspace_root`, `application_root`, `archive_directory`, `knowledge_database_path` and the backup receipt point to `F:\GPT projects\Projects\…`.
`current_release_zip` still points to v0.3.45 and `current_verification_entrypoint` to VERIFY-20261017-0345.
`last_review_*` and `latest_review_*` duplicate each other. Proposal: one metadata update record through `knowledge-db.py`.

### 4. Knowledge DB data quality
- `priority` mixes `1`, `2`, `high`, `medium`, `low`, `normal` (2,359 `normal`) — sort/filter by priority is unreliable.
- 3,876 of 7,249 evidence rows (53 %) are in `stale_evidence`.
- 90 open findings, 19 high-priority; several were never re-checked against current code, e.g. ARRFIND crawler page advance, quality score overwritten with zero, Reimagined full/gaps filter, 6 terse `converted code: …` .NET findings, SQLite WAL-reset patch provenance.
- Proposal: normalize priority to one scale; one pass to re-verify or close the 19 high findings; refresh stale evidence for unchanged files.

### 5. No schema version stamp (runtime DBs)
`user_version = 0`; migrations are column-presence checks, so downgrades are undetectable. Set `application_id` + `user_version` and refuse newer schemas. (The knowledge DB already uses `user_version = 1`.)

### 6. Missing FK index
`CREATE INDEX IF NOT EXISTS idx_tag_reviews_right ON tag_reviews(right_id)` in both runtimes.

### 7. Small code corrections
- `catalog_exchange.py:331` — `choices.inspect()` result per row discarded, then recomputed.
- `BoundedLruCache` — no capacity guard; racing `GetOrAdd` hit doesn't refresh recency.
- `DatabaseSession.Execute` quietly starts a write transaction inside a `Read` session.
- 24 ruff unused locals/imports (12 safe autofixes).

### 8. Tests not green on the target platform
14 Windows-only Python collection errors; the C# suite uses a custom `Exe` runner. Gate releases on one Linux run inside the built image; consider NUnit/xUnit so `dotnet test` works.

### 9. Supply-chain pinning
Mutable base-image tags; app `pip install` without hashes. Pin by digest, `--require-hashes`.

### 10. Housekeeping (AutoSourcarr-related, keep but slim)
100+ `dotnet-build-prior-*` logs, 12 one-shot `close_stageNN_gate.py`, stale `autosourcarr reimagined/` folder,
Windows-only `.test-deps`, 422 KB changelog, space-stripped `PROJECT_CONTEXT.md`. The Kotlin package path is
10–13 folders deep, which also blocks remote file tools.
