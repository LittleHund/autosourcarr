6e DESIGN (decided 01:00, record as decision at phase end):
- Egress broker: C# HTTP/CONNECT proxy on 127.0.0.1:<random port>, allowlist of domains per repair job (the source's site(s) + dependency repos), sends no Via header, uses an honest User-Agent ("AutoSourcarr/<version> source repair") on plain HTTP, refuses everything else with 403 and logs it.
- Runner: new native/repair-runner.c (the Landlock-only process runner; the KVM microVM in repair-launcher.c has no guest image or agent yet).
  - Requires Landlock ABI >= 4 (network rules) and refuses otherwise.
  - FS: read-only libraries, the JDK and the toolchain; read-write job dir only; nothing else (so no /config, no /data).
  - NET: connect only to the proxy port; bind nothing.
  - no_new_privs, cleared caps, seccomp reused from repair-launcher.
  - Executes the build command (java/javac/jar tools) in the job dir.
- Repair path for "a known orphan is repaired": a domain/API migration. A source whose website moved: AddressResearch/WebsiteProbe find the new address (needs an IWebsiteObservationTransport implementation through the proxy/PublicSourceFetcher). The repair rewrites the old base URL in the extension's code. Options: (a) constant-pool string rewrite of the host-converted JAR, or (b) recompile from the raw code (RawStore) with javac/kotlinc in the runner. Pick (a) first; it needs no compiler. Then structure check, install via the host (install-file), content check through the host (search → details → chapters → pages → image, as in source-host-check.py), keep the last working version (RepairHistory/RawStore), rollback.
- CI proof in the probe: build repair-runner.c with gcc; a test runs `cat /config/...` and `curl https://example.com` inside the runner (both must fail), and the allowed proxy domain works.
- Opt-in auto repair: the watch switch exists (SourceMaintenanceState); a daily job type reads source health failures and queues a repair when watch is on.
- Paced traffic: a per-site pace in SourceTransportManager or the host's SourceBackoff (the host already backs off); add a minimum interval per source in the host (setting SOURCE_MIN_INTERVAL_MS).
